【任务】实现ARGUS的约束生成框架，替换当前"自由生成Z3代码"的教师Agent逻辑。

【背景】
当前系统在L2/L3任务上invalid率>95%，根因是LLM自由生成Z3代码时频繁出现语法错误（括号不匹配、变量未声明、约束矛盾）。需通过三层约束将生成过程限制在"语法合法+逻辑可解"的空间内。

【交付物】修改以下文件：
1. population/teacher/generate.py
2. scripts/z3_runner.py（增加JSON渲染函数）
3. config.yaml（增加课程学习参数）

【实现要求】

**第一层：JSON骨架生成**
- 修改教师Agent的system prompt，要求输出JSON而非Python代码
- JSON schema：
  {
    "variables": [{"name": "a", "type": "Int"}, ...],
    "constraints": ["a + b == 7", "a >= 0", ...],
    "expected_sat": true
  }
- 支持的type：Int, BitVec（需指定位宽，如"BitVec32"）, Array
- constraints列表中的每一项必须是合法的Z3表达式字符串

**第二层：确定性渲染**
- 在z3_runner.py中增加函数：
  def render_z3_code(task_json: dict) -> str:
      """将JSON骨架渲染为完整的Z3 Python代码。保证括号匹配、变量声明完整。"""
- 渲染规则：
  - 第一行：from z3 import *
  - 变量声明：{name} = {type}('{name}')
  - BitVec类型：{name} = BitVec('{name}', {width})
  - Solver初始化：solver = Solver()
  - 约束：逐条 solver.add({constraint})
- 如果JSON schema不合法，抛出明确异常

**第三层：符号约束反馈**
- 修改generate_task函数签名：
  def generate_task(level, llm, round_num, condition, extra_constraints=None, max_retries=5):
- 当Z3验证失败时，根据错误码归纳符号约束：
  - error_code=4（timeout）：追加"减少约束数量到5个以内"
  - error_code=1（syntax）：追加"所有变量必须声明类型"
  - error_code=2（no_solver）：由渲染引擎自动保证，不需反馈
- 将累积的extra_constraints注入下一轮prompt

**第四层：课程学习控制器**
- 新增文件：scripts/difficulty_controller.py
- 子级别定义：
  SUB_LEVELS = {
    1: [3, 5, 8, 10],   # L1的变量数
    2: [5, 10, 15],      # L2的变量数
    3: [5, 10]           # L3的变量数
  }
- 升级条件：当前子级别连续5轮有效任务率>80%
- 降级条件：当前子级别连续3轮有效任务率<50%
- 状态持久化到 state/difficulty_state.json

【验收标准】
- 用Mock LLM跑4条件×20轮，L1任务invalid率<10%
- JSON schema不合法时抛出明确异常，不静默失败
- 渲染后的Z3代码通过ast.parse语法检查
- 课程控制器能正确升级/降级，状态文件正确读写
