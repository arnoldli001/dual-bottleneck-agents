【任务】重新分析已有2400轮日志，生成两种统计口径的Δ_t对比表，解决审稿人质疑"Table 2与full_run_analysis数据矛盾"。

【背景】
- full_run_analysis.md 报告 A=0.15, B=0.00（仅valid轮次）
- table2_delta_t_summary.md 报告 A=0.2435, B=0.2450（含invalid轮次，invalid编码为Δ_t=1.0）
- 两处数据看似矛盾，实际是统计口径不同，需在论文中明确区分

【交付物】
1. scripts/reanalyze_delta_t.py
2. reports/table2b_delta_t_valid_only.md（仅valid轮次的Δ_t）
3. reports/table2c_delta_t_semantics.md（A/B的Δ_t定义澄清）
4. reports/fig2b_delta_t_per_round.png（逐轮Δ_t曲线，非分桶）

【实现要求】

**Part 1：生成两种口径的Δ_t表**
读取 logs/{A,B,C,D}/round_*.jsonl，对每一轮计算：
- 如果该轮是 invalid（有 invalid_task 事件）：Δ_t_global = 1.0，Δ_t_valid = None
- 如果该轮 valid（有 solution_verified 事件）：
  - Δ_t_global = Δ_t_valid = |llm_self_score/100 - true_label|
  - 其中 true_label = 1.0 if z3_result.status == expected else 0.0

输出两张表：
- Table 2b（valid-only）：每个条件的 avg Δ_t，仅统计 valid 轮次，附带 n_valid
- Table 2c（global）：每个条件的 avg Δ_t，含 invalid 轮次（编码为1.0），附带 n_total

**Part 2：A/B的Δ_t语义澄清**
生成 reports/table2c_delta_t_semantics.md，明确写出：
- 条件A：Δ_t = |LLM自评分 - Z3真值|，衡量"LLM自评与形式真值的偏差"
- 条件B：Δ_t = |LLM自评分 - Z3真值|，但Z3锚定作为最终判定，因此valid轮次的"系统评估"就是Z3真值，Δ_t恒为0.00
- 关键：A/B使用相同的Δ_t公式，但A的"系统评估"是LLM自评，B的"系统评估"是Z3锚定

**Part 3：逐轮Δ_t曲线（非分桶）**
绘制 fig2b_delta_t_per_round.png：
- X轴：轮次 1-200（每个条件取第1次run）
- Y轴：Δ_t（仅valid轮次，invalid用灰色×标记）
- 4条线：A（红）、B（绿）、C（橙）、D（蓝）
- 标注：A的Δ_t稳定在0.15，B的Δ_t稳定在0.00
- 标注：C/D在升L2后Δ_t急剧扩大（用灰色阴影标注L2起始轮次）

【验收标准】
- Table 2b 中 B 的 avg Δ_t = 0.00（与 full_run_analysis 一致）
