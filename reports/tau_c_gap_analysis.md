# Task 4 (P1) — τ_c(D) vs τ_c(B): hypothesis audit

> **τ_c 数据来源**：`real API (P0-2)`

> **结论先行：受控实验不支持「τ_c(D) > τ_c(B)」这一假设。**
> 在难度钉定于 L1 的真实 API τ 扫描中，B 与 D 得到相同的 τ_c，
> 且没有任何 τ 触发退化判据。详见 §1 与 §5。

## 1. τ_c 实测值

| 条件 | τ_c (Δ_t 口径) | τ_c (正确率口径) | 综合 τ_c |
|------|---------------|----------------|---------|
| B | 0.55 | 0.55 | 0.55 |
| D | 0.55 | 0.55 | 0.55 |

- τ_c(B) = **0.55**，τ_c(D) = **0.55**
- 差值 = 0 → **无 gap**

### 1.1 为什么早期 mock 数据给出了错误的 gap

早期 mock sweep（`reports/tau_c_analysis.md`）报告 τ_c(B)=0.55、τ_c(D)=0.90。
该差异来自 mock 的两个特性，而非真实机制差异：

1. **任务内容逐轮固定**：MockLLM 对每个 (condition, round) 返回相同 payload，
   Δ_t 退化为 {0,1} 的二值序列，50 轮里的 late/early 比值噪声极大。
2. **判据在小样本上不稳定**：mock 的 τ=0.90 档出现 early=0.0 / late=0.167 的
   偶发组合，被 1.5× 比值判据标为「退化」，从而把 D 的 τ_c 推到 0.90。

真实 API 下任务内容逐轮不同、Δ_t 分布更平滑，该假象消失。

## 2. 仍然成立的部分：B 与 D 的难度分布确实不同

从 2400 轮**未约束**真实实验中提取各级别的 valid 任务产出
（legacy 数据，τ=1.0；反映基线生成器能力）：

| 条件 | L1 valid数 / 总数 (valid率) | L2 valid数 / 总数 | L3 valid数 / 总数 | invalid 总数 |
|------|---------------------|----------------|----------------|------------|
| B | 453/453 (100.0%) | 0/0 (—) | 0/0 (—) | 147 |
| D | 6/6 (100.0%) | 4/4 (100.0%) | 47/47 (100.0%) | 543 |

> ⚠️ **该表的 valid 率列不可用于跨条件比较**：
> 分母只包含「产生了 task_generated 事件」的轮次，
> 而两个条件的 invalid 轮次都没有级别标签、无法归入任何级别。
> B 的 453 个 valid 全是 L1；D 的 57 个 valid 里有 51 个在 L2/L3。

在 2400 轮 τ=1.0 实测中，D 的 invalid 总数（543）是 B（147）的 3.7 倍。
原因并非 D 的锚定失效，而是 D 的种群博弈机制把任务推到 L2/L3，
而生成器在 L2/L3 的 invalid 率显著上升（详见 fig3 / fig3b）。

## 3. 假设为什么不成立：受控实验的反证

原始假设（Proposition 2）的推理链是：

1. D 的种群博弈把任务推到 L2/L3；
2. L2/L3 的生成器无效任务更多（invalid = Δ_t 1.0）；
3. 因此在同样的 τ 噪声下，D 的 Δ_t 退化更早被触发 → τ_c(D) 更高。

**第 1、2 步成立，第 3 步不成立。**

- 第 1 步：成立。D 有 57 个 valid 轮次中 51 个在 L2/L3；
  B 的 453 个 valid 全部在 L1。
- 第 2 步：成立。D invalid 率 90.5% vs B 24.5%。
- 第 3 步：**不成立**。P0-2 的受控 τ 扫描（难度钉定 L1、每 cell 全新经验库）
  显示 B 与 D 的 τ_c 相同，且无任何 τ 触发退化判据。

### 3.1 第 3 步失败的原因

把难度钉定在 L1 恰好**移除了第 1 步那个机制本身**——
D 的种群博弈没有机会升级难度，于是两个条件在 τ 实验中成为等价配置。
这是实验设计的正常后果，不是矛盾：

| 实验 | 难度 | 两条件是否可区分 | τ_c 结果 |
|------|------|----------------|----------|
| P0-2 τ 扫描 | 钉定 L1 | 否（机制被禁用） | B = D = 0.55（网格下界）|
| 2400 轮完整实验 | 自适应 | 是（D 升到 L2/L3） | 未做 τ 扫描 |

要真正检验第 3 步，需要一个**允许难度自适应**的 τ 扫描：
让 τ 噪声同时作用于难度升降决策，观察是否出现「噪声 → 错误升级 →
进入 L2/L3 → 生成器崩溃 → Δ_t 上升」的正反馈。本任务未做该实验。

## 4. 论文表述（修正版，对应 Section 5.4）

> The mock-LLM sweep suggested τ_c(D) > τ_c(B), which we initially read as
> D paying a price for pushing tasks into L2/L3. The real-API sweep does
> **not** reproduce this gap: with difficulty pinned to L1, both conditions
> return the same threshold. Pinning the difficulty removes precisely the
> mechanism the hypothesis invoked. We therefore report the difficulty
> -distribution difference (§2) as an observation and do not claim it
> translates into a higher judge-reliability requirement.

> 直译：mock 曾提示 τ_c(D) > τ_c(B)，我们最初解释为 D 因任务更难而付代价。
> 真实 API 扫描**未复现**该差距：难度钉定 L1 时两条件阈值相同。
> 钉定难度恰好移除了该假设依赖的机制。因此我们把难度分布差异（§2）
> 作为观察报告，不声称它转化为更高的裁判可靠度要求。

## 5. 仍然成立的定量结论

去掉「τ_c 更高」这个不成立的推论后，以下事实仍可用于论文：

1. **难度分布差异**：B 在 L2/L3 的占比 = 0/453 = 0.0%；
   D = 51/57 = 89.5%。
   D 是 B 的 895 倍——种群博弈确实改变了任务复杂度分布。
2. **复杂度与无效率的关联**：L2/L3 的 valid 率远低于 L1（见 fig3b）。
3. **噪声的稳态效应**：在无状态反馈的配置下，Δ_t(τ) = (1-τ²)/2，
   与 Ratchet 的瞬时翻转概率一致，但不产生渐进退化。
4. **负结果本身**：受控实验否定了「机制越多 ⇒ 对裁判噪声越敏感」的直觉。
   在 L1 静态配置下，D 的额外机制（经验记忆 / 蒸馏 / 圆桌）
   没有使它对噪声更脆弱。
