二、四层约束生成框架（论文 Section 6）

基线的失败模式是「LLM 自由生成 Z3 代码」——括号不匹配、变量未声明、约束矛盾。 本节管线把生成过程限制在「语法合法 ∧ 逻辑可解」的空间内。

1
JSON 骨架生成：教师 prompt 要求输出 {variables, constraints, expected_sat} 而非 Python 代码
agents.py · TEACHER_SYS_JSON
2
确定性渲染：模板拼接为 Z3 代码，括号与声明由构造保证； schema 非法则抛 TaskJSONInvalid，不静默失败
z3_runner.py · render_z3_code
3
符号反馈：Z3 错误码 → 符号级 hint （超时→「约束数减到 5 个以内」），注入下一轮 prompt
agents.py · _ERROR_CODE_TO_SYMBOLIC
4
课程控制器：子档位变量数，5 连 ≥80% 升级 / 3 连 <50% 降级， 状态持久化
scripts/difficulty_controller.py

五、裁判可靠度 τ 实验（论文 Section 5）

对每个 Z3 判决以概率 p = (1−τ)/2 翻转 SAT↔UNSAT（error / unknown 永不翻转）。 每轮有两次独立判决被注噪：教师任务验证 + 学生答案验证。

P(correct) = (1−p)² + p² = (1+τ²)/2   ⟹   Δ_t(τ) = (1 − τ²) / 2   （无自由参数）
反推设计公式： τ_c = √(1 − 2·Δ_t_max)
验证项结果
解析拟合 MAE（条件 B / D）0.0258 / 0.0520
判别性检验：实测 correct_rate vs 本模型MAE 0.039
判别性检验：vs「裁判判断 + 系统接受」模型（P=τ²）MAE 0.229（被排除）
双重瓶颈合成律 1−Δ_global=(1−Δ_gen)(1−Δ_judge) 最大误差 1.11e-16
τ_c 实测（L1 隔离）B = D = 0.55（网格下界，非拐点）

六、核心结果

6.1 双重瓶颈

一轮「成功」需要 (i) 教师产出有效任务 且 (ii) 学生判对。 按概率链式法则，两个瓶颈共享同一个 Δ_t 预算。 2400 轮四条件验证，误差在机器精度量级。

第八节的差异不是「实现偏离设计」的缺陷，而是研究推进的自然结果： 蓝图画的是通用自进化 Agent，最终仓库交付的是回答一个具体研究问题所需的最小系统。 未实现的规划项（三环嵌套、Agent 状态机、FAISS、云端 GPU 调度）在第九节列出。

九、设计蓝图中未实现的规划项

层规划项为何未做
L5风险信号网、人类闸门离线实验中无人在环需求；成本硬上限已覆盖治理目标
L4变异算子池、跨域迁移器、假设空间扩展器超出「测量裁判可靠度阈值」这一研究问题
